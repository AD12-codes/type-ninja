# Algorithm content guide

All typing content for typeninja lives in this package. Nothing is generated by
AI at runtime: every snippet and explanation is a checked-in file that gets
seeded into the database.

```
content/
  snippets/<language>/<slug>.<ext>   # one file per algorithm per language
  explanations/<slug>.md             # one language-agnostic explanation
src/catalog.ts                       # algorithm metadata (name, category, complexity)
src/languages.ts                     # supported languages + indent unit + extension
```

Run `bun test` in this package to validate everything.

## Snippet rules

The snippet is what the user types, character for character, so it must be
short, idiomatic and comment-free.

1. **Correct, idiomatic code** for that language. It must compile / parse.
2. **Only the implementation**: the function(s) or class that implement the
   algorithm. No `main`, no tests, no example calls, no `package main`,
   no `namespace`/`class Program` wrappers (Java/C#/Kotlin: a bare
   `public static` method or top-level `fun` is fine), no `#include` unless the
   code genuinely needs it (C/C++ may include `<vector>`, `<string>`, etc.).
3. **No comments** of any kind.
4. **Indentation** uses spaces only, with the per-language unit from
   `src/languages.ts` (python 4, javascript 2, typescript 2, go 4, rust 4,
   java 4, csharp 4, cpp 4, c 4, lua 4, ruby 2, kotlin 4). Never tabs.
5. **Line length** at most 64 characters. Prefer under 56.
6. **Length** between 5 and 45 lines. Aim for 8–30.
7. ASCII only, LF line endings, no trailing whitespace, no blank first line,
   no two consecutive blank lines, and the file ends with exactly one newline.
8. Keep names consistent across languages using each language's convention:
   `bubble_sort` (python, ruby, lua, rust, c), `bubbleSort` (javascript,
   typescript, go, java, kotlin, cpp), `BubbleSort` (csharp).
9. Prefer data structures from the language's standard library when idiomatic
   (`deque` in python, `container/list` or a slice in go, `std::vector` in
   C++, `java.util.ArrayDeque` in Java...). Imports go at the top of the file
   and count toward the line budget.
10. The snippet for a given slug should implement the same behaviour and
    signature shape in every language (e.g. `two-sum` returns the pair of
    indices; `binary-search` returns the index or -1; `coin-change` returns
    the minimum coin count or -1).

Reference: `content/snippets/python/bubble-sort.py`.

## Explanation rules

One markdown file per algorithm, independent of programming language. It is
rendered in the app with a mermaid flow diagram.

Required structure, in this order:

```
# <Algorithm name exactly as in src/catalog.ts>

## Overview
One or two short paragraphs in plain English.

## How it works
A numbered list of steps.

## Flow
A single ```mermaid fenced block with a `flowchart TD` diagram of the
algorithm's control flow. Quote node labels that contain brackets or
special characters, e.g. H{"arr[j] > arr[j+1]?"}.

## Complexity
A markdown table with Best / Average / Worst time and Space rows, each with a
one-line justification. Values must match `src/catalog.ts`.

## When to use
Bullet list.

## Pitfalls
Bullet list of common mistakes.
```

Reference: `content/explanations/bubble-sort.md`.
